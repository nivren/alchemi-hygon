## 2. 当前任务队列

参考版本按以下顺序推进，每一项可拆成独立可验证的小里程碑：

1. **项目文档**：整理现有 README、环境、应用能力、当前状态、交接和开发入口；
   历史过程以快照、原报告与版本记录追溯。
2. **应用示例**：围绕数据与邻居、模型单点、固定胞 dynamics、固定/变胞弛豫、
   BFGS及多阶段流程，逐项准备、验证并编写必要说明。示例范围以实际代码与证据为准。
3. **交付验证**：检查独立检出、环境依赖、示例、文档链接与范围限制，再形成参考版本。

示例可以使用外部模型和结构文件；输入包括分子晶体结构预测批量结构和锂钠化合物结构。
路径、模型与数据通过参数提供，不假定其他机器具备 dcu2 本地路径。
应用专属配置、CIF批处理和可选 FastEq 集成属于独立的 `alchemi-app`，不要据此扩大本工程声明。

每个阶段和小里程碑开始前先向用户说明目标、范围和预期结果；完成后总结实现、
验证与限制，获得用户明确确认后才开始下一项。参考版本发布、推送和标签须有对应授权。

## 3. 明确暂停项

- NPT/NPH、长程相互作用、单大体系 DomainParallel 和真实 MLIP 完整训练尚无完整 DCU 应用验收。
- planner 后续阶段及生产 Triton/HIP dynamics 不因文档整理自动启动。
- 升级上游、Torch/DTK、系统安装、长作业和多卡占用须明确范围及授权。
- 性能结论仅适用于具体输入、设备与测试条件；HIP 不自动进入 `auto`。

## 4. 并行边界

按锁定上游源码、operation contract、测试和现有后端边界拆分独立工作，避免同一文件
同时被多个开发分支修改；按任务分支、显式路径暂存和短提交组织。项目当前没有要求
并行启动开发任务；涉及并行工作的安排以用户指令和资源条件为准。

## 5. 标准开工和验收流程

先检查分支、工作树、相关 diff 和已有报告；改动算法或设备路径先确认输入输出、
精度、PBC、容量、错误、stream 与梯度契约，并建立适用的 reference/oracle。
按照影响运行独立 CPU 测试；触及 HCU 路径时在已分配或确认空闲的设备上做限时验证，
资源不可用时记录范围，不占用他人资源。实现、测试、数值结果和未验证项分别报告。
详见[开发指南](DEVELOPMENT_GUIDE.md)与[环境指南](DEVELOPMENT_ENVIRONMENT.md)。

## 6. 暂停条件

目标不明确、现有改动无法安全避开、契约与证据矛盾、需超出已确认里程碑的重大选择、
或设备/依赖阻塞必须取得的验收时，记录已完成工作并与用户确认；不要覆盖、重置或
将未验证能力写为已支持。历史授权不延续为新的推送、合并或发布授权。
