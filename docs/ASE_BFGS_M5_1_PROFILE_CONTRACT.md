# ASE BFGS M5-1：性能定位合同

2026-10-10，用户确认启动。基于M1–M4已通过的当前实现，交付可重复性能基准、
Jacobi关键路径证据、小规模CSP端到端占比及M5-2方案。本阶段不改产品数学、
求解器、构建准入、版本锁或默认选择；探针中的分项调用只用于测量。

## 输入、范围与数值门

- 当前匹配环境：项目HCU Torch2.9.0+das.opt1.dtk2604 / DTK26.04，FP64、
  full eigensystem、forward-only，显式HIP后端。单个空闲HCU有界顺序运行。
- 真实147/285维Hessian沿用M4捕获材料，B1/B4；B4为相同矩阵副本，记录此限制。
  另测147/285/147异构组，保持实际DOF分组，无padding或逐体系分解。
- CPU FP64 LOWER oracle、谱atol=2e-10/rtol=2e-11；相对方程及正交误差<1e-10，
  检查info、输入不变、有限性。比较谱与方向，不逐列比较简并特征向量。
- raw native和拆出的guard/clone/layout计时不是支持更弱检查的产品候选；
  任何实际候选均先通过现有数值/ASE门，再评估性能。

## 测量与验收

1. 记录环境、源码/输入/模型hash、精确命令、目标和profiler退出码。
2. JIT加载与首调用分开；预热2次后每项至少7个样本，保留wall及stream event
   原始值，报告中位数、范围、标准差；正常计时与profiler/debugger严格分开。
3. 对照raw native、完整checked eigh、输入/输出检查、clone/layout、有效性守卫，
   加上真实DOF分组BFGS更新。分项计时是独立窗口，不能直接相加作为端到端拆账。
4. 限时hipprof采集真实147/285 Jacobi的kernel、4字节收敛读取及同步；区分API等待
   与GPU执行，避免重叠累计；使用实际帮助选项，不启用PMC或CoreDump。
5. 使用既有46/92原子MPA-0 FIRE2→变胞BFGS工作流，在相同checkpoint/CIF/参数下
   做小规模完整运行及预热窗口测量。记录成功结构、步数、模型求值和总耗时；
   仪表化耗时不能当作无开销吞吐或性能提升。
6. 根据瓶颈选择M5-2：封装/调度优化或自研HIP batched Jacobi原型，并给出
   可证伪假设、明确范围、数值门和性能门。实际优化保留门建议为同输入稳态中位数
   至少10%下降、跨重复运行可见且端到端有收益；本阶段不预先承诺可达。

代码、测试结果、数值与性能证据分别报告。新增探针仅提供测量接口，产品支持状态
保持M4范围；26.10当前与Torch不匹配且DC含CPU子块数学，不作为本阶段替代后端。
完成后总结，再由用户确认M5-2；不自动提交、推送或合并。
